# LLM Prompt Studio · LLM 提示词工作室

在 **Stable Diffusion Forge Neo** 里，用中文描述画面，让大语言模型（LLM）写出适合绘图模型的提示词；也可以整理已有提示词、从图片反推标签，再交给 Forge 生图。图片始终由 Forge 当前加载的绘图模型生成，插件只负责"把提示词写对、写散、写得能用"。

适合这些场景：批量出图但不想每张都手写 prompt、角色或 LoRA 固定但画面要变化、已有 prompt 需要转换/扩写/润色、有一堆图片要反推标签。

## 核心能力

| 能力 | 说明 |
| --- | --- |
| 提示词生成 | 单条 / 批量 / 持续生成；支持固定主体、逐条创作要求、随机题材、静态词库抽样 |
| 批量多样性 | 代码从词库抽配方（动作/场景/道具/光线…），覆盖式调度 + 内容级去重 + 跨批次记忆 |
| 提示词处理 | 对已有缓存做格式转换、扩写、润色；显示完成/未完成/失败数量，可继续未完成项 |
| 两个独立缓存库 | 原始提示词与处理结果分开保存；支持筛选、编辑、批量管理、撤销删除 |
| 生图联动 | 文生图内嵌面板使用当前 Forge 参数逐轮生成，支持无限循环；也可仅缓存或写入提示词框 |
| 本地图片反推 | 内置 WD14 / CL Tagger，自动发现本地模型，支持单图与文件夹批量 |
| 模板与推理参数 | 自定义快速模板；工作室与内嵌面板共享已保存的推理参数，可配置备用连接 |
| 多服务商 | OpenAI Responses / Chat Completions、Anthropic、Gemini、OpenRouter、DeepSeek、Ollama、LM Studio、自定义 OpenAI 兼容接口 |
| 交接 API | 供 PNG 提示词采集器、Ranbooru 等插件把原始 Prompt 送进来处理 |

输出格式支持：Danbooru 标签、Danbooru + 自然语言、自然语言、NoobAI 标签、Anima 标签、Krea 2 自然语言，以及区域 JSON / Markdown。

## 安装

先准备可正常生图的 Forge Neo。在「扩展 → 从网址安装」中填写：

```text
https://github.com/Rivulet138/sd-webui-llm-prompt-studio.git
```

或在 **Forge Neo 根目录**执行：

```powershell
git -C extensions clone https://github.com/Rivulet138/sd-webui-llm-prompt-studio.git
```

安装后重启 Forge，并用 `Ctrl + F5` 刷新浏览器。沿用平时的 `webui-user.bat` / `webui.bat` 启动即可，生图队列**不需要**额外添加 `--api`。

## 配置 LLM

打开 **LLM Prompt Studio → 设置**，填写服务提供方、服务地址、模型 ID 和 API Key，点「测试连接」，成功后「保存并应用」。模型 ID 可手填，也可用「发现模型」选择。

- **模型 ID**：生成提示词的大语言模型。
- **系统提示词预设**：决定输出标签还是自然语言、字段顺序与长度。
- **模型预设**：在生成页选择，让提示词适配目标绘图模型。
- **实际绘图模型**：始终是 Forge 当前加载的模型。

温度、Top P、Top K、输出 Token、超时与推理选项在设置页统一保存；工作室与内嵌批量生成共用这些参数，实际可用字段取决于所选服务与模型。主连接失败可回退到独立配置的备用连接。

「插件实时交接箱」有一套独立的推理参数：首次使用继承主连接，保存后只影响交接箱处理，不改变常规生成设置；处理时仍沿用当前工作流预设与安全分级。

## 快速上手

1. 打开「生成」页，在「创作要求」里描述画面，例如 `雨后的街道，一位撑伞的旅人，暖色路灯`。
2. 选择输出格式预设与模型预设，数量设为 `1`，去向选「仅保存到缓存」。
3. 点「生成到缓存」，在结果框看提示词，在「缓存」页找到记录。

需要直接用完整文生图参数出图时：在 Forge 的 **文生图** 页面设好模型、尺寸、采样器，展开 **Prompt 批量生成**，选「前端连续生图（使用当前 txt2img 参数）」，点「开始前端生图」。结果显示在 Forge 原生图库。

## 提示词是怎么生成的

系统提示词不是一段大杂烩，而是按六个层次组装。改文案时请对号入座：

### 六层结构

| 层 | 作用 | 谁能改 |
| --- | --- | --- |
| ① 统一策略 `PROMPT_POLICY_V3` | 不可协商的硬规则：只输出载荷、单图、只写可见事实、禁用风格/画质/艺术家词、固定内容不可变、模型原生锚点、长度预算、安全、冲突自查 | 代码（`prompt_studio_core.py`） |
| ② 输出格式预设 | 格式 + 字段顺序 + 长度带宽（标签行 / 段落） | 「当前生效内容」编辑框可覆盖这一层 |
| ③ 底模规则 | 该模型族的词表、顺序、权重上限、锚点能否使用 | 代码 |
| ④ 质量锚点策略 | 能用哪些原生锚点、不许发明 | 代码 |
| ⑤ 操作语义 | 生成 / 转换 / 扩写 / 润色的差异 | 代码 |
| ⑥ 本批次指令 | 本条配方、已覆盖概念、未使用方向 | 运行时自动注入 |

「当前生效内容」只替换第②层，其余五层恒在——所以自定义正文不会把安全或禁用词规则一起改没。

想直接看拼装结果？打开 **「提示词」页 → 系统提示词预览 → 刷新预览**，会打印当前设置下真正发给模型的全文（不含本批次配方）。

### 长度预算

| 输出格式 | 长度 |
| --- | --- |
| Danbooru 标签 | 8–60 个标签 |
| Danbooru 标签 + 自然语言 | 8–40 个标签 + 至多 1 个自然语言从句 |
| 自然语言 | 30–200 词 |
| NoobAI 标签 | 8–60 个标签 |
| Anima 标签 | 6–50 个标签 |
| Krea 2 自然语言 | 70–160 词 |

长而密的提示词会压制变化、稀释底模与 LoRA 的表现，所以长度是硬约束，不是建议。

### 风格 / 媒介 / 画质 / 艺术家词约束

生成的 Prompt 只描述画面本身（主体、外观、动作、环境、道具、空间、构图、时间天气、光线、颜色材质），**不得引入**风格、媒介、画质或艺术家词：`masterpiece`、`best quality`、`8k`、`artstation`、`octane`、`cinematic lighting`、任何艺术家或工作室名等。这类词会和底模、LoRA 争夺风格主导权，而不是把画面说清楚。

这条约束只写在**统一策略**一处（其余各层不重复），并由契约测试守住，防止文案回潮。你自己固定在 Prompt 里已写的词会按原样保留，只禁止新增。

例外：所选模型自带的官方锚点（如 Pony V6 的 `score_9, score_8_up, …`）按该模型模板保留。

### 批量多样性：配方 / 覆盖 / 去重 / 记忆

批量、内嵌连续、自动循环生成共用一套机制，默认开启：

- **配方抽样**：每条任务从已索引词库按「动作 / 场景 / 物品 / 表情 / 光线 / 镜头 / 颜色」各抽 1 项，组成该条必须体现的 `REQUIRED LOCAL RECIPE`。人物、服饰等身份类目录不参与；与固定 Prompt 冲突时以固定内容为准。
- **覆盖式调度**：批次内按维度组合轮转，前 C(7,3)=35 条的维度组合互不相同，而不是每次独立随机；目录抽样做了逆频率加权，避免大词库压住小词库。
- **内容去重**：比较前先剥离所有条目共享的主体骨架词（兽耳、尾巴、`wearing` 等），只比场景、动作、道具、材质。命中阈值时换配方重试一次（最多额外 1 次调用）；即使仍接近，也会返回本批最不像的一条，不会返回空结果。
- **覆盖式提示**：批次指令同时给出「本批已覆盖的概念」与「尚未使用的方向」——模型对否定式约束的处理明显弱于肯定式锚点。
- **源重复检测**：批次预览会统计「多少条输入其实描述同一画面」。这些输入不会带来新画面，多样性完全取决于配方与去重；默认只统计不删，需要自动折叠时开 `source_fold_duplicates`。
- **跨批次记忆**：结果按「源 Prompt」记最近 6 组 × 16 条，写入 `settings.prompt_diversity_memory_v1`，重启后继续生效。
- **单条生成不受影响**：只有带批次指令的任务才启用配方与去重。

所有参数都在 **「提示词」页 → 批量多样性参数** 里图形化调；也可以写 `settings` 表的 `prompt_diversity_v1`（JSON，便于脚本化与复现），改完下一次生成生效：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `recipe_enabled` | `true` | 关闭后不注入配方，仅保留去重 |
| `recipe_dimensions` | `3` | 每条配方抽取的维度数（1–6） |
| `retry_limit` | `1` | 每条最多额外重试次数（0–3） |
| `similarity_threshold` | `0.55` | 内容相似度阈值（0.2–0.95），越低越严格 |
| `memory_enabled` | `true` | 是否读写跨批次记忆 |
| `batch_temperature_floor` | `false` | 开启时批量内温度不低于 1.25；默认保持你保存的温度 |
| `source_fold_duplicates` | `false` | 开启后自动折叠内容几乎相同的输入 |

## 使用手册

### 「提示词」页

所有跟提示词本身相关的开关集中在这一页：

| 区域 | 做什么 |
| --- | --- |
| 提示词说明 | 六层结构各自负责什么、哪一层可编辑 |
| 批量多样性参数 | 配方开关与维度数、去重重试次数、内容相似度阈值、跨批次记忆、温度下限、自动折叠重复输入；保存后下一次生成生效，取值越界自动夹紧 |
| 系统提示词预览 | 一键打印当前设置下拼装出的完整系统提示词，方便核对与复制 |
| 缓存库多样性统计 | 只读统计最近 N 条缓存的 distinct-n / Self-BLEU / Vendi / 内容余弦，不写库、不调用 LLM |

### 生成与批量

单条与批量都在「生成」页。需要保留的角色标签、主体、LoRA 或权重放进「固定 Prompt」，本次画面要求放进「创作要求」。

- **数量 1**：生成一条。
- **数量 2–200**：按数量批量生成。
- **数量 0**：持续执行，直到点「停止」或遇到停止条件。

展开「批量选项」可逐行填写独立要求：正数模式按列表执行（最多 200 条），`0` 模式循环使用该列表。创作要求留空时可使用随机题材与静态词库抽样。

选「仅保存到缓存」不会生图。数量为 `0` 且选生图时，每轮只提交一条，等绘图结束再继续。「本次结果」提供待重试项；无限模式展示最近 200 条，完整成功结果在缓存中。

### 文生图内嵌面板

展开 txt2img 正面提示词框下方的 **Prompt 批量生成**：

| 来源 | 可用操作 |
| --- | --- |
| LLM 自动生成 | 写入 Prompt、仅保存到缓存、前端连续生图 |
| 原始缓存库 | 写入 Prompt、前端连续生图 |
| 处理结果库 | 写入 Prompt、前端连续生图 |

写入或生图时可设追加、替换等合并方式；仅缓存不会改动提示词框。两个缓存库按记录顺序读取、末尾自动循环，每次只取下一条，不受前 1000 条限制，也不把整库载入浏览器；数据库本身没有插件设置的总数上限，容量取决于磁盘。

选「前端连续生图」后，数量为正按轮数生成，`0` 表示持续到停止。每轮相当于点一次 Forge 原生「生成」，使用提交时的负面提示词、采样器、步数、尺寸、CFG、Seed、批量、Hires 与脚本参数；一轮出图数量由 Forge 的批次数与批量大小决定。每轮提交后恢复固定 Prompt，保留你期间新增或删除的 LoRA。

工作室「生成」页与「处理结果库」里的「加入生图队列」是另一条独立服务端队列，只传递其支持的部分参数。需要与手动点 Forge 完全一致的参数与脚本时，用内嵌入口。

### 缓存与处理结果库

「缓存」保存生成、导入、反推得到的原始提示词；「处理结果库」单独保存转换/扩写/润色后的结果。

1. 打开 **生成 → 缓存 Prompt 处理**（默认收起），筛选并选择记录，或选「全部筛选结果」（含全部分页）。
2. 选处理操作并开始。界面显示已处理 / 未处理 / 失败数量，暂停后可「继续处理未完成」。
3. 成功结果自动存进处理结果库，可直接入队或以追加／替换写入 txt2img。处理结果库有独立的保守推理参数（默认温度 0.25，服务商/地址/模型/凭据继承主连接），在「处理结果库独立 LLM 参数」中保存，只影响缓存处理。只有显式选「覆盖原始缓存」才改写原始记录。

原始缓存支持关键词、格式、目标模型筛选，每页 50 条；编辑与删除合并入口，批量修改与按全库序号删除也合并入口，并支持撤销删除。处理结果库提供「批量管理结果」。导入支持 JSON / CSV；导出包含全部原始缓存，不受当前筛选与分页影响。

### 图片反推（WD14 / CL）

打开 **更多 → WD14 / CL 反推**，检测并选择本地模型。插件会扫描 Forge 模型目录、已装 WD14 插件目录、Hugging Face 缓存与指定的额外目录，无需另装反推插件。

| 模型类型 | 同目录内需要的文件 |
| --- | --- |
| WD14 ONNX | `.onnx` 模型 + `selected_tags.csv` |
| CL Tagger 1.01 | `.onnx` 模型 + `tag_mapping.json` |

没有模型时可自行下载后重新检测；打开面板与检测**不会**自动下载。

- **单张图片**：上传反推，可编辑结果、交给 LLM 继续处理，再送入 txt2img 或存进原始缓存。
- **文件夹批量**：填目录，可勾选「包含子文件夹」，支持 PNG / JPG / WEBP / BMP / TIFF / GIF，支持停止、继续未完成、重试失败。
- **使用批量结果**：存进缓存，或「全部送入 txt2img 批量列表」（装载到 Forge 的 `Prompts from File or Textbox` 脚本，仍需手动点「生成」）。

反推在本地运行，输出的是标签估计；只有选 LLM 处理时才调用已配置的模型服务。文件夹任务的续跑状态只在当前服务进程内，重启后需重新扫描。

### 模板与静态词库

工作室与 txt2img 共用自定义快速模板，支持编辑、保存、设为默认、删除；同名保存更新原模板，新名称另存。模板用于「创作要求」与变化规则。

「更多 → 静态词库」支持 TXT / CSV / JSON / YAML，按目录和文件分类索引；选中词条可「追加到固定 Prompt」。改完词库要重新索引；索引失败时保留上一次有效数据。

### 交接 API

其他插件把原始 Prompt 送进来处理：

- `POST /llm-prompt-studio/v1/handoff`：推荐显式带 `schema: "prompt_studio.handoff.v1"`、`source_kind`、`prompt`（也接受 `raw_prompt`）；可选 `source_ref`、`negative_prompt`、`metadata`。
- `POST /llm-prompt-studio/v1/handoff/process`：请求体可直接复用同一份交接 JSON，也可传已有交接 ID。

显式 schema 优先走通用协议，避免与旧版 Ranbooru 字段误判；未带 schema 的旧请求仍兼容。`metadata` 需为可 JSON 序列化且不超过 32KB 的对象；Prompt 与负面 Prompt 合计不超过 16000 字符。

## 后台运行与停止

**内嵌连续生图**：点「开始前端生图」后，插件会尝试使用仅供自身等待调度的后台 Worker，以便页面切到后台或窗口最小化后继续提交下一轮。页面须保持打开且未被浏览器冻结或丢弃，Forge 与电脑须保持运行；页面冻结、被丢弃或电脑休眠期间不保证继续。前端 Prompt 队列存在当前浏览器的 localStorage，刷新后只恢复为待处理状态，不会自动续跑。

Forge 原生右键菜单的 **Generate forever** 仍由 Forge 控制；单独使用该入口时，可在 Forge 设置中开启 `Keep generating even when the WebUI browser tab is not in focus`（`keep_alive`）后刷新页面。

已提交的服务端生图任务在关闭页面后仍可由 Forge 执行；依赖页面的连续生成在关闭页面后不会创建下一轮。启动 Forge、打开或刷新页面不会自动开始生图，也不会续跑上次未完成任务。

- 点「停止」结束后续提示词生成，已完成缓存保留。
- 服务端队列的「取消」会取消等待项，并在当前任务仍归属该队列时请求 Forge 中断；归属无法确认时按取消/未知处理，不会自动重复执行。
- 一级无限任务连续 3 次 LLM 失败后停止；关闭「失败后继续」则首次失败即停。无限生图遇到队列失败、取消或任务丢失也会停止。
- `0 = 无限` 只适用于标明该含义的数量控件；页码、区域数量等仍用各自范围。

## 度量提示词多样性

只读脚本，不写库、不参与生成：

```bash
# 统计当前库里已有的提示词
python scripts/prompt_studio_diversity.py --db user/prompt_studio.db

# 统计一份文本文件（每行一条），并输出 JSON
python scripts/prompt_studio_diversity.py --file prompts.txt --json

# 只看前 8 条；自定义近重复阈值
python scripts/prompt_studio_diversity.py --limit 8 --threshold 0.5
```

输出 `distinct-1/2/3`、`Self-BLEU-3/4`、`Vendi` 与平均内容余弦。判读：

- `Vendi` 接近条数 → 真实多样；接近 1 → 几乎每条都是同一画面。
- `Self-BLEU` 越低越好；`mean content cosine` 越低越分散。

指标与运行时去重共用同一套词表与分词，所以"去重通过"和"报告好看"不会各说各话。

## 数据、备份与隐私

本地数据都在扩展目录的 `user/`（已在 `.gitignore` 中）：

| 路径 | 内容 |
| --- | --- |
| `user/prompt_studio.db` | 原始提示词、设置、模板、词库索引、队列记录 |
| `user/processed_prompt_cache.db` | 缓存处理结果 |
| `user/credentials/llm_credentials.json` | 按服务商与地址保存的 API Key（界面不回填明文） |
| `user/exports/` | 导出文件 |
| `user/backups/` | 删除操作的恢复备份 |
| `assets/wildcards/` | 随插件提供的静态词库 |

备份配置与缓存时，先关闭 Forge 再复制 `user/`。该目录含凭据，不要公开上传。内置下载的反推模型位于 **Forge 模型目录的 `WD14/`** 下，需另行备份。

## 更新与排错

在 Forge 根目录执行，然后重启 Forge 并用 `Ctrl + F5` 刷新：

```powershell
git -C extensions/sd-webui-llm-prompt-studio pull --ff-only
```

| 现象 | 检查 |
| --- | --- |
| 更新后页面缺失 / 模块不存在 | 确认扩展完整更新，重启 Forge，刷新浏览器 |
| LLM 连接失败 | 核对服务商、地址、模型 ID、凭据；兼容接口通常需要正确的 `/v1` 路径 |
| HTTPS / TLS 握手失败 | 检查代理或服务端；插件不会自动降级为 HTTP |
| 检测不到反推模型 | 确认 ONNX 与标签文件成对，指定额外目录后重新检测 |
| 提示缺少反推依赖 | 在 Forge 使用的 Python 环境安装提示的依赖（`onnxruntime`、`numpy`、`Pillow`；自动下载用 `huggingface_hub`） |
| 有提示词却没生图 | 确认是否选了仅缓存或写入；需要生图时选入队或点 Forge「生成」 |
| 批量结果仍然很像 | 看批次预览的"源重复"提示；用上面的多样性脚本量一次；必要时调低 `similarity_threshold` |
| 提示词出现风格/画质词 | 确认没有改坏系统策略；跑 `python -m unittest test_prompt_contract` 应全绿 |
