# LLM Prompt Studio · LLM 提示词工作室

## 项目介绍

LLM Prompt Studio 是一款运行在 **Stable Diffusion Forge Neo** 中的提示词管理与生成扩展。你可以用中文描述想要的画面，让大语言模型（LLM）生成适合绘图模型的提示词（Prompt），也可以整理已有提示词、从图片反推标签，再交给 Forge 生图。

插件将提示词生成、批量处理、本地缓存和生图队列放在同一个工作台中。生成结果可以先保存备用，也可以直接加入生图队列；图片仍由 Forge 当前加载的绘图模型生成。

适合需要批量创作、保留固定角色或画风、复用历史提示词，以及整理大量图片标签的用户。

## 主要功能

| 功能 | 可以做什么 |
| --- | --- |
| 提示词生成 | 单条、批量或持续生成，支持固定主体、逐条创作要求、随机题材与词库抽样 |
| 提示词处理 | 对已有缓存进行格式转换、扩写和润色，查看完成数量并继续未完成任务 |
| 两个独立缓存库 | 分开保存原始提示词与处理结果，支持筛选、编辑和复用，大库按记录顺序读取 |
| 生图联动 | 选择仅缓存、写入提示词框或加入队列，生图时读取当前文生图参数 |
| 本地图片反推 | 内置 WD14 / CL Tagger，检测本地模型，支持单图、文件夹和子文件夹批量反推 |
| 模板与模型设置 | 自定义快速模板、系统提示词和输出格式；工作室与文生图内嵌面板共享已保存的推理参数 |
| 多服务商连接 | 支持云端或本地 LLM，备用连接可独立设置服务商、地址、模型和凭据 |

LLM 连接支持 OpenAI Responses / Chat Completions、Anthropic、Gemini、OpenRouter、DeepSeek、Ollama、LM Studio 和自定义 OpenAI 兼容接口。输出支持标签、自然语言及区域 JSON / Markdown。

## 开始使用

### 1. 安装插件

先准备可以正常生图的 Forge Neo。在「扩展 → 从网址安装」中填写本项目地址：

```text
https://github.com/Rivulet138/sd-webui-llm-prompt-studio.git
```

也可以在 **Forge Neo 根目录**执行：

```powershell
git -C extensions clone https://github.com/Rivulet138/sd-webui-llm-prompt-studio.git
```

安装后重启 Forge，并用 `Ctrl + F5` 刷新浏览器。沿用平时的 `webui-user.bat` 或 `webui.bat` 启动即可，生图队列不需要额外添加 `--api`。

### 2. 配置大语言模型

打开 **LLM Prompt Studio → 设置**，填写服务提供方、模型服务地址、模型 ID 和 API Key，点击「测试连接」，成功后「保存并应用」。模型 ID 可以手动填写，也可以通过「发现模型」选择。

- **模型 ID**：负责生成提示词的大语言模型。
- **系统提示词预设**：决定输出标签、自然语言等提示词形式。
- **模型预设**：在生成页选择，用于让提示词适配目标绘图模型。
- **实际绘图模型**：仍使用 Forge 当前加载的模型。

温度、Top P、Top K、输出 Token、超时及推理选项在设置页统一保存。工作室与文生图内嵌批量生成共用这些参数；具体可用字段以所选服务和模型为准。主连接失败后可回退到独立配置的备用连接。

如果只使用本地图片反推，可以先跳过 LLM 配置，直接使用下文的「图片反推」。

### 3. 生成第一条提示词

1. 打开「生成」页，在「创作要求」中描述画面，例如：`雨后的街道，一位撑伞的旅人，暖色路灯，电影感构图`。
2. 选择系统提示词预设和模型预设，将生成数量设为 `1`，去向设为「仅保存到缓存」。
3. 点击「生成到缓存」，在结果框查看提示词，在「缓存」页找到保存记录。

需要直接生图时，先在 Forge 的 **文生图（txt2img）**页面设置绘图模型、尺寸、采样器等，再将生成去向改为「生成并加入生图队列」。插件会先保存提示词，再提交生图并显示进度和图片。

## 常用操作

### 批量与持续生成

单条和批量生成都在「生成」页。需要保留的角色标签、主体、LoRA 或权重放入「固定 Prompt」，本次画面要求放入「创作要求」。

- **数量为 1**：生成一条。
- **数量为 2–200**：按指定数量批量生成。
- **数量为 0**：持续执行，直到点击「停止」或遇到停止条件。

展开「批量选项」可以逐行填写独立要求。填写后，正数模式按输入列表执行（最多 200 条），`0` 模式循环使用该列表。创作要求留空时可使用随机题材与静态词库抽样。

选择「仅保存到缓存」不会生图。数量为 `0` 且选择生图时，每轮只提交一条，等待绘图结束后继续。「本次结果」提供待重试项；无限模式展示最近 200 条记录，完整成功结果保存在缓存中。

### 在文生图页面调用提示词

展开 txt2img 正面提示词框下方的 **Prompt 批量生成**，选择来源和操作：

| 来源 | 可用操作 |
| --- | --- |
| LLM 自动生成 | 写入 Prompt、仅保存到缓存、加入生图队列 |
| 原始缓存库 | 写入 Prompt、加入生图队列 |
| 处理结果库 | 写入 Prompt、加入生图队列 |

选择写入时，可设置追加、替换等合并方式；选择仅缓存或入队时，固定提示词框保持不变。两个缓存库按记录顺序读取，末尾自动循环，每次仅取下一条，不受前 1000 条限制，也不把整库载入浏览器。数据库没有插件设置的记录总数上限，实际容量取决于磁盘空间。

「开始连续生图」启动原生 txt2img 连续流程，每轮临时提交提示词后恢复固定内容。生图队列读取提交时的负面提示词、采样器、步数、宽高、CFG、Seed、批量和 Hires 参数；图片保存在 Forge 的正常输出目录。

### 处理与复用缓存

「缓存」保存生成、导入和反推得到的原始提示词；「处理结果库」单独保存原始缓存经过转换、扩写、润色后的结果。

1. 打开 **生成 → 缓存 Prompt 处理**（默认收起），筛选并选择记录，或选择「全部筛选结果」。该范围包含全部分页。
2. 选择处理操作并开始。界面显示已处理、未处理和失败数量，暂停后可「继续处理未完成」。
3. 成功结果自动保存到处理结果库，可直接入队或以追加／替换方式写入 txt2img。只有显式使用「覆盖原始缓存」才会改写原始记录。

本次任务尚未处理完时也可以提交已完成结果，重复点击会跳过本次已提交项。历史结果在「处理结果库」选择「所选结果」或「全部筛选结果」后入队；空选不会自动提交全库。底部「缓存结果生图队列」用于查看进度和图片。

原始缓存支持关键词、格式、目标模型筛选，每页 50 条，并提供编辑、批量修改、删除和撤销删除。导入支持 JSON / CSV；导出包含全部原始缓存，不受当前筛选和分页影响。

### 图片反推

打开 **更多 → WD14 / CL 反推**，检测并选择本地模型。插件会扫描 Forge 模型目录、已有 WD14 插件目录、Hugging Face 缓存和指定的额外目录，无需另装反推插件。

| 模型类型 | 同一目录内需要的文件 |
| --- | --- |
| WD14 ONNX 模型 | `.onnx` 模型和 `selected_tags.csv` |
| CL Tagger 1.01 | `.onnx` 模型和 `tag_mapping.json` |

没有模型时，在下载区域自行选择并下载，或通过面板提供的链接手动下载后重新检测。打开面板和检测模型不会自动下载。

- **单张图片**：上传图片并反推，可编辑结果、交给 LLM 继续处理，再送入 txt2img 或保存到原始缓存。
- **文件夹批量**：填写目录，按需勾选「包含子文件夹」，支持 PNG、JPG、WEBP、BMP、TIFF、GIF，以及停止、继续未完成和重试失败。
- **使用批量结果**：保存到缓存，或点击「全部送入 txt2img 批量列表」。后者装载到 Forge 的 `Prompts from File or Textbox` 脚本，仍需手动点击 Forge「生成」。

图片反推在本地运行，输出的是标签估计；选择 LLM 处理时才调用已配置的模型服务。文件夹任务的续跑状态保留在当前服务进程中，重启后需重新扫描。

### 模板与词库

工作室和 txt2img 共用自定义快速模板，支持编辑、保存、设为默认和删除。同名保存更新原模板，新名称另存；模板用于创作要求和变化规则。

系统提示词（System Prompt）在「当前生效内容」中编辑。切换预设会替换正文；内置正文跟随模型适配，自定义正文在切换模型时保留。通过「工作参数 → 保存当前参数」保存修改，「恢复所选预设」取消覆盖。

「更多 → 静态词库」支持 TXT、CSV、JSON、YAML，按目录和文件分类索引，选中词条后可「追加到固定 Prompt」。修改词库后重新索引；失败时保留上一次有效数据。

## 后台运行与停止

**最小化浏览器或切到桌面继续生图**：开启 Forge 设置中的 `Keep generating even when the WebUI browser tab is not in focus`（`keep_alive`，即浏览器失去焦点时仍继续生成），应用设置并刷新页面。浏览器页面、Forge 进程和电脑须保持运行。

已经提交的服务端生图任务在关闭页面后仍可由 Forge 执行。依赖页面的连续生成在关闭页面后不会继续创建下一轮；启动 Forge、打开或刷新页面不会自动开始生图，也不会自动续跑上次未完成任务。

- 点击「停止」结束后续提示词生成，已完成的缓存保留。
- 「取消等待中的生图」取消尚未执行的队列项；正在绘图时使用 Forge 的「中断」。
- 一级无限任务连续 3 次 LLM 失败后停止；关闭「失败后继续」则在首次失败时停止。无限生图遇到队列失败、取消或任务丢失也会停止。
- `0 = 无限` 只适用于标明该含义的生成数量控件，页码、区域数量等仍使用各自范围。

## 数据与备份

本地数据位于扩展目录下的 `user/`：

| 路径 | 内容 |
| --- | --- |
| `user/prompt_studio.db` | 原始提示词、设置、模板、词库索引和队列记录 |
| `user/processed_prompt_cache.db` | 缓存处理结果 |
| `user/credentials/llm_credentials.json` | 按服务商和地址保存的 API Key，界面不回填明文 |
| `user/exports/` | 导出文件 |
| `user/backups/` | 删除操作的恢复备份 |
| `assets/wildcards/` | 随插件提供的静态词库 |

备份配置与缓存时，先关闭 Forge 再复制 `user/`。该目录包含凭据，不应公开上传。内置下载的反推模型位于 **Forge 模型目录的 `WD14/` 下**，需按需另外备份。

## 更新与问题排查

在 Forge 根目录执行以下命令后，重启 Forge 并用 `Ctrl + F5` 刷新页面：

```powershell
git -C extensions/sd-webui-llm-prompt-studio pull --ff-only
```

| 问题 | 检查方法 |
| --- | --- |
| 更新后缺少页面或提示模块不存在 | 确认扩展完整更新，重启 Forge 后刷新浏览器 |
| LLM 连接失败 | 核对服务商、地址、模型 ID 和凭据；兼容接口通常需要正确的 `/v1` 路径 |
| HTTPS / TLS 握手失败 | 检查代理或服务端连接；插件不会自动降级为 HTTP |
| 检测不到反推模型 | 检查 ONNX 与标签文件是否成对，指定额外目录后重新检测 |
| 提示缺少反推依赖 | 在 Forge 使用的 Python 环境中安装提示的依赖；推理使用 `onnxruntime`、`numpy`、`Pillow`，自动下载使用 `huggingface_hub` |
| 已有提示词却没有生图 | 检查是否选择了仅缓存或写入；需要生图时选择入队或点击 Forge「生成」 |
